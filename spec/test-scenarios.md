# Основные пользовательские сценарии для тестирования

## A. Публичное бронирование (гость)

### A1. Просмотр списка типов встреч
- **Запрос:** `GET /api/public/event-types`
- **Ожидаемый результат:** 200, массив типов встреч

### A2. Просмотр доступности на 14 дней
- **Запрос:** `GET /api/public/event-types/{eventTypeId}/availability`
- **Ожидаемый результат:** 200, массив из 14 объектов с полями `date`, `available`, `total`
- **Негативный:** несуществующий eventTypeId → 404

### A3. Просмотр свободных слотов на дату
- **Запрос:** `GET /api/public/event-types/{eventTypeId}/slots?date=YYYY-MM-DD`
- **Ожидаемый результат:** 200, массив слотов (будни, 9:00–18:00, не прошлые, не забронированные)
- **Негативные:** неверный формат даты → 400; нет параметра date → 400; несуществующий eventTypeId → 404; выходные → пустой массив; дата более 14 дней → пустой массив

### A4. Создание бронирования
- **Запрос:** `POST /api/public/bookings`
- **Тело:** `{ slotId, eventTypeId, guestName, guestEmail }`
- **Ожидаемый результат:** 200, созданное бронирование
- **Негативные:**
  - слот уже занят → 409
  - невалидный email → 400
  - пустое имя → 400
  - несуществующий eventTypeId → 404
  - невалидный slotId → 400
  - некорректный JSON → 400

## B. Управление типами встреч (владелец)

### B1. Список типов встреч
- **Запрос:** `GET /api/event-types`
- **Ожидаемый результат:** 200, массив типов встреч

### B2. Создание типа встречи
- **Запрос:** `POST /api/event-types`
- **Тело:** `{ name, duration, description? }`
- **Ожидаемый результат:** 200, созданный тип встречи
- **Негативные:** duration не 15 или 30 → 400; пустое name → 400; некорректный JSON → 400

### B3. Обновление типа встречи
- **Запрос:** `PUT /api/event-types/{eventTypeId}`
- **Тело:** `{ name, duration, description? }`
- **Ожидаемый результат:** 200, обновлённый тип встречи
- **Негативные:** несуществующий eventTypeId → 404; некорректный JSON → 400

### B4. Удаление типа встречи
- **Запрос:** `DELETE /api/event-types/{eventTypeId}`
- **Ожидаемый результат:** 200, `{ status: "deleted" }`
- **Негативные:** несуществующий eventTypeId → 404
- **Каскадное удаление:** связанные бронирования удаляются, слоты освобождаются

## C. Управление бронированиями (владелец)

### C1. Просмотр бронирований владельца
- **Запрос:** `GET /api/owners/{ownerId}/bookings`
- **Ожидаемый результат:** 200, массив обогащённых бронирований (с startTime, endTime, eventTypeName)
- **Крайний случай:** у владельца нет бронирований → пустой массив

### C2. Удаление бронирования
- **Запрос:** `DELETE /api/bookings/{bookingId}`
- **Ожидаемый результат:** 200, слот освобождается
- **Негативные:** несуществующий bookingId → 404

## D. Вспомогательная бизнес-логика

### D1. Формирование слотов (`enumerateSlots`)
- Для буднего дня возвращается 36 слотов по 15 мин или 18 слотов по 30 мин (9:00–18:00)
- Для выходного дня возвращается пустой массив
- Для даты более 14 дней возвращается пустой массив

### D2. Формат slotId (`makeSlotID` / `parseSlotID`)
- Формат: `{eventTypeId}-{unixTimestamp}`
- Парсинг: корректное восстановление startTime и date
- Невалидные строки → ошибка

### D3. Проверка буднего дня (`isWeekday`)
- Суббота и воскресенье → false
- Понедельник–пятница → true

### D4. Валидация слота (`isSlotValid`)
- Слот в рабочее время на будний день в пределах 14 дней → true
- Слот после 18:00 → false
